## 记录流程

1. 一次交互围绕一个任务，给出任务编号与关联需求。
2. 保存实际提示词及多轮追问。原始回复单独存入 `conversations/`，按实际平台能力导出或复制；不要把概述冒充原文。
3. 任务结束后在 `usage-log.md` 追加一条记录，标明 AI 输出、人工判断、AI 再修改和验证结果。
4. 有代码时引用实际文件与 Git 提交；有测试时保存实际输出，必要截图放入 `evidence/`。
5. 组员核对 AI 整理的日志，填写实际采纳情况和人工贡献；阶段结束时据此编写 AI 使用总结。

建议文件名：`AI-003_数据库结构_2026-10-15.md`。目录内尚未存在的原始交互或证据，不应在日志中标记为已保存。

## 真实性约定

- 工具和模型按界面实际显示记录，不知道的写未知，不推测具体模型版本。
- AI 实现、AI 根据反馈修复、组员直接修改分别记录。
- 用户要求某个结果不等于用户亲自设计了全部实现，人工贡献写具体行为和理由。
- 没有生成代码则写无；未执行测试则写未执行；未复核则写待复核。
- 错误只记录实际发现且有依据的错误，不刻意编造案例。
- 分享或提交前检查配置、密钥和个人信息；需要脱敏时说明脱敏范围，保留可核查原件。

